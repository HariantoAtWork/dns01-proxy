# Fix Proxy Host add killing all Source LEDs

Adding or updating a Proxy Host always rebound edge `:443` with stop-then-start. If the new listener failed to bind (slow port release after drain, or a bad SNI set), the process left HTTPS down until a container restart — so every Source LED went Offline even though upstream forwards were fine.

Edge HTTPS now overlap-binds the next SNI set with `SO_REUSEPORT` before draining the old listener, rolls back to the previous TLS material if bind fails, retries bind more aggressively, and heals in the background when `:443` is still down.
